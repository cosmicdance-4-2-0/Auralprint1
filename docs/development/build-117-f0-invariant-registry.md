## Purpose and classification

F0 makes protected promises independently testable *before* replacing the Analysis or Visualization implementation. The goal is a reviewable registry of **invariant → current owner → breaking counterexample → evidence pointer → unresolved proof**. It does **not** introduce a new source of policy, promote a draft to a contract, or prescribe future module layout.

Evidence labels used below:

- **Source inspected:** an owning file was read at the pinned accepted source. It is not an executed test.
- **Mapped test:** the named existing test was inspected for its assertions. It is a candidate regression gate, **not** a new pass in this F0 session.
- **Recorded prior run:** a historical run documented by the 117 baseline or merged PR; it is not a test result at this new branch head.
- **Gap:** a guarantee or circumstance needing a new proof, owner decision, or specific native/device evidence.

For each counterexample, **reject** means the candidate 117 implementation must prevent that condition or fail without corrupting authoritative state. A counterexample is a *test design*, not a claim that the current release exhibits the defect.

## F0 exit and change rules

F0 is ready for **owner review** when each registry entry identifies (1) the existing authority/implementation, (2) a failure-class counterexample, (3) a mapped existing proof or explicit gap, and (4) the next boundary decision. Any disputed invariant must remain visibly open; passing unrelated tests cannot settle it.

F0 is *accepted* only after the owner reviews the registry against current source, corrects missing promises, and explicitly approves it as the migration checklist. Acceptance of this document **does not** close Stage 0 measurements or approve F1/F2 API proposals, Stage 3/3.5 migration, a preset schema, performance tradeoffs, or release.

This checkpoint is documentation-only: no `src/`, tests, build/watch scripts, package/dependencies, CONFIG, presets, `version`, Canon, archived fixtures, or production runtime changes are authorized or necessary. The [AGENTS Definition of Done](../../AGENTS.md) and [ROADMAP Stage 0/1 gates](../../ROADMAP.md) remain in force.
